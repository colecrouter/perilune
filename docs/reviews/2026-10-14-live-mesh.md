# Live bed mesh review

An independent agent reviewed the physical command lifecycle, regression coverage,
and deployment assumptions before merge. The review approved the implementation
and the follow-up protocol/UI corrections after actionable findings were resolved.

Resolved findings:

- Revalidate captured prior mesh identity before homing and again before probing;
  revalidate destination profile conflicts before saving.
- Verify restored mesh contents, not only its profile name.
- Preserve the workflow ID, plan and prior mesh metadata on all recovery paths.
- Retain review/uncertain reservations after failed finish actions.
- Retry only durable journal writes after storage failure, never physical commands.
- Fence late RPC/query replies across generations and retain newer telemetry.

Hardware verification found newer Klipper probe-response syntax using probe
coordinates, and a brief post-probe busy interval. Both response formats now have
coordinate-aware progress coverage; finish/restore controls wait for idle telemetry.

Authorized cold hardware verification completed probing, new-profile configuration
saving with restart verification, and restoration of the original default mesh.
The original default profile and off heater targets were preserved. A real transport
interruption also exercised uncertain-outcome handling without command replay;
recovery was followed by a deliberate fresh run. No private connection details,
printer configuration, measured grid or camera captures are included in this review.

Validation includes domain/service/transport tests, headless browser regressions,
and an additional stateful production smoke for the enabled live workflow.
